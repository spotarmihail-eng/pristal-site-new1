НОВОСТИ ИЗ DISCORD:
Сайт автоматически получает последние 10 сообщений канала ID 1486375854006206494. Workflow GitHub Pages синхронизирует новости каждые 10 минут.

Чтобы включить автоматическую ленту:
1. Создайте Discord-бота в Discord Developer Portal (или используйте уже существующего бота).
2. Добавьте бота на ваш Discord-сервер и дайте ему права View Channel и Read Message History именно в канале новостей. Для обычного чтения сообщений privileged Message Content Intent может понадобиться включить на странице Bot в Developer Portal.
3. В GitHub откройте репозиторий сайта → Settings → Secrets and variables → Actions → New repository secret.
4. Имя секрета: DISCORD_BOT_TOKEN. Значение: токен Discord-бота. Не вставляйте токен в HTML, JS или сообщения.
5. Откройте Actions → Deploy Pristal to GitHub Pages → Run workflow, либо дождитесь следующего автоматического запуска. При успешном подключении лента появится на сайте.

Проверка: в Actions должен завершиться workflow Deploy Pristal to GitHub Pages. Если новостей нет, проверьте токен и права бота на канал. Секрет хранится в GitHub Actions и не отправляется в браузер.

Сайт остаётся статическим и совместим с GitHub Pages; Discord API вызывается только из GitHub Actions.

ВХОД ЧЕРЕЗ DISCORD:
Кнопка «Войти через Discord» в шапке использует OAuth2 (implicit grant, scope identify). Сайт получает только ник и аватар; токен не сохраняется.
1. Откройте discord.com/developers/applications → ваше приложение (или New Application) → OAuth2.
2. Скопируйте Client ID и вставьте в index.html: const CLIENT_ID="..." (блок pristal-discord-auth). Client ID — не секрет.
3. OAuth2 → Redirects → Add Redirect: адрес сайта ровно как в браузере, со слэшем в конце, например https://ник.github.io/pristal-site/
4. Client Secret на сайт НЕ вставляйте.
Важно: профиль хранится только в браузере посетителя. Списка зарегистрированных пользователей у сайта нет, а закрывать что-либо «входом» нельзя — для этого нужен сервер.

=====================================================================
ПРОФИЛИ И ПРИВЯЗКА MINECRAFT (вкладка «Профиль», profile.html)
=====================================================================
Как это устроено
  Сайт (GitHub Pages) -> API на Cloudflare Worker + база D1 (папка backend/) <- плагин Paper/Spigot (папка minecraft-plugin/).
  1. Вход через Discord: браузер отдаёт токен API, а API САМ проверяет его в Discord (и что токен выдан именно вашему приложению).
  2. «Привязать Minecraft»: сайт просит ник -> API создаёт одноразовый код вида A7K9-P2MX (действует 5 минут, в базе хранится только его хэш).
  3. Игрок заходит на сервер и пишет /link A7K9-P2MX. Плагин сам берёт ник игрока из игры и шлёт его в API с секретным ключом.
  4. API проверяет: ключ плагина, код (не истёк, не использован), что ник из игры совпадает с введённым на сайте, и что ник не занят другим аккаунтом.
  5. Только после этого статус на сайте становится «Привязан». Браузеру верить нельзя — ник и результат приходят ТОЛЬКО от плагина.

Установка (один раз)
  A. API. Нужен бесплатный аккаунт Cloudflare и Node.js. В папке backend/:
       npx wrangler login
       npx wrangler d1 create pristal                -> скопируйте database_id в wrangler.toml
       (в wrangler.toml также укажите ALLOWED_ORIGIN — адрес сайта без слэша, например https://ник.github.io)
       npx wrangler d1 execute pristal --remote --file=schema.sql
       npx wrangler secret put PLUGIN_KEY            -> введите длинную случайную строку (40+ символов), например из: openssl rand -hex 32
       npx wrangler deploy                           -> в конце будет адрес вида https://pristal-api.<аккаунт>.workers.dev
  B. Сайт. В config.js впишите этот адрес в API и залейте сайт на GitHub. Вход через Discord (CLIENT_ID и Redirect) настраивается как раньше.
  C. Плагин. В GitHub откройте Actions -> «Build Minecraft plugin» -> Run workflow, затем скачайте PristalLink.jar из Artifacts.
     Положите jar в папку plugins сервера (Aternos: нужен Paper/Spigot, раздел «Файлы» или «Плагины»), запустите сервер один раз,
     откройте plugins/PristalLink/config.yml: впишите api-url (адрес Worker) и api-key (ТА ЖЕ строка, что PLUGIN_KEY). Перезапустите сервер.
  D. Проверка: на сайте «Профиль» -> «Привязать Minecraft» -> введите ник -> в игре выполните показанную команду.

Безопасность и пиратские (offline-mode) серверы
  * В offline-mode любой игрок может зайти под ЧУЖИМ ником. Поэтому без плагина авторизации привязка ника доказывает только «я сейчас сижу
    в игре под этим ником». Установите AuthMe (или аналог) и оставьте в config.yml require-auth-plugin: true — тогда /link работает
    только у игроков, вошедших по паролю. Без AuthMe при true команда будет отказывать.
  * UUID в offline-mode вычисляется из ника и ничего не доказывает — он только сохраняется для справки.
  * PLUGIN_KEY никогда не кладите в сайт или репозиторий. config.yml плагина с ключом тоже не публикуйте.
  * Один ник нельзя привязать к двум аккаунтам. Отвязка — с подтверждением. Коды одноразовые; неверные попытки ограничиваются.
  * Не реализовано: админ-панель (разрешить привязку одного ника нескольким аккаунтам, принудительная отвязка).
    Принудительная отвязка вручную: npx wrangler d1 execute pristal --remote --command "DELETE FROM links WHERE nick_lower='ник_в_нижнем_регистре'"

---------------------------------------------------------------------
РЕЖИМ БЕЗ ПЛАГИНА (по умолчанию: LINK_MODE = "simple" в backend/wrangler.toml)
---------------------------------------------------------------------
  Пользователь вводит Minecraft-ник во вкладке «Профиль» и он привязывается сразу, без команды в игре. Подходят пиратские аккаунты.
  Плагин, PLUGIN_KEY и шаг C из инструкции выше НЕ нужны. Нужны шаги A (кроме команды secret put PLUGIN_KEY) и B: база и API по-прежнему
  требуются, чтобы хранить привязки и не давать привязать один ник к двум аккаунтам.
  Ограничения этого режима:
   * Ник НЕ подтверждается сервером: любой может привязать любой свободный ник (кто первый). Привязка не доказывает, что это его ник.
   * Если ник занял не тот человек — удалите привязку командой (в папке backend/):
       npx wrangler d1 execute pristal --remote --command "DELETE FROM links WHERE nick_lower='ник_в_нижнем_регистре'"
   * Привязку не стоит использовать для выдачи привилегий, доступа к вайтлисту и т.п., пока ник не подтверждается.
  Чтобы вернуть подтверждение через игру: LINK_MODE = "plugin", шаг C и повторный деплой (npx wrangler deploy).

ЛОКАЛЬНЫЙ РЕЖИМ (по умолчанию, пока в config.js пустой API) — ничего разворачивать не нужно
---------------------------------------------------------------------
  После входа через Discord во вкладке «Профиль» можно менять никнейм и аватарку и привязывать Minecraft-ник (в том числе пиратский).
  Всё хранится в браузере посетителя (localStorage). Плагин, Cloudflare и база не нужны.
  Ограничения: данные не видны на других устройствах и вам как администратору; уникальность ников не проверяется; ник не подтверждается сервером.
  Когда понадобятся общие данные и уникальность ников — разверните backend/ (см. выше) и впишите адрес в config.js.
