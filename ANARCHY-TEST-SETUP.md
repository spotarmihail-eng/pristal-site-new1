# Настройка заявок на закрытое тестирование Pristal

Система использует только GitHub Pages, GitHub Actions и Discord Bot API. Отдельный сервер не нужен. Проверка запускается примерно раз в 5 минут; GitHub может задерживать scheduled-запуски.

## 1. Подготовить канал Discord

1. Создай текстовый канал, например **#заявки-анархия**, на сервере Pristal.
2. Разреши участникам отправлять сообщения, а боту — просматривать канал и историю сообщений, отправлять сообщения и добавлять реакции.
3. Включи Developer Mode в Discord и скопируй ID канала.
4. Добавь бота на сервер. В Discord Developer Portal включи **Message Content Intent**.
5. Убедись, что администратор и бот состоят на сервере. Администратору должны быть доступны личные сообщения от бота.

Важно: сообщения в обычном текстовом канале видны всем участникам, у которых есть доступ к этому каналу. Не проси заявителей указывать пароли, личные контакты и другие секретные сведения.

## 2. Добавить GitHub Secrets

Открой репозиторий → **Settings → Secrets and variables → Actions → New repository secret** и добавь:

- `DISCORD_BOT_TOKEN` — токен Discord-бота.
- `APPLICATION_CHANNEL_ID` — ID канала заявок.
- `ADMIN_DISCORD_ID` — Discord ID администратора, которому бот будет присылать заявки.

Токен бота не добавляй в HTML, config.js, workflow или сообщения чата.

## 3. Разрешить GitHub Actions записывать файлы

Открой **Settings → Actions → General → Workflow permissions** и выбери **Read and write permissions**. Это нужно, чтобы workflow мог обновлять JSON со статусами.

## 4. Как работает модерация

1. Участник входит через Discord на главной странице Pristal и открывает `anarchy-test.html`.
2. Указывает Minecraft-ник, копирует подготовленную заявку и отправляет её в **#заявки-анархия**.
3. Бот добавляет к сообщению реакции ✅ и ❌ и присылает администратору личное сообщение со ссылкой на заявку.
4. Администратор ставит на исходном сообщении ровно одну реакцию: ✅ — одобрить, ❌ — отказать.
5. При следующем запуске workflow бот проверяет реакцию именно от Discord ID, указанного в `ADMIN_DISCORD_ID`, и обновляет статус. Участник увидит его на странице тестирования; бот также попробует отправить решение ему в личные сообщения.

Если администратор поставит обе реакции, решение останется на рассмотрении — убери лишнюю реакцию и дождись следующей проверки.

## 5. Запуск и проверка

Открой **Actions → Pristal anarchy applications → Run workflow** для первого запуска. Затем workflow будет запускаться по расписанию раз в 5 минут. Проверь журнал запуска, если бот не отвечает.

Статусы хранятся в `anarchy-test-status.json` под SHA-256-хешем Discord ID, без публикации самого ID. Этот JSON общедоступен вместе со статическими файлами сайта, поэтому статус нельзя считать секретной информацией. Сам токен бота и сырые Discord ID в публичный JSON не записываются.
